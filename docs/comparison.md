# Comparing controllers

[Back to project](../README.md)

Generate a report from the stored research runs:

```bash
python -m rl_ems.comparison.report --input simu_results/wef_ms --output outputs/historical-report
```

Or arrange new simulations as `outputs/cases/rl_rl`, `outputs/cases/rl_mpc`, etc., then use `--input outputs/cases`. Each case needs `mg_data.pkl` and `crop_data.pkl` generated by the simulator. Only load trusted project pickle files.

The command writes `metrics.csv` and `comparison.png`. It reports grid import (negative energy residual with sign reversed), signed net residual, total irrigation and absolute daily irrigation-tracking error. Energy residuals are already kWh per interval; no second time conversion is applied. Initial state rows are excluded. Unlike the historical percentage error, absolute error includes days with zero requested water.

Case names follow **irrigation controller_energy controller**: `rl_mpc` means RL irrigation and MPC pumping. The historical `ewms_results.py` uses different MPC variants in some pairings; the new simulation CLI consistently selects the shrinking-horizon `MPCPumpingPolicy`. Do not treat these as identical experimental configurations.

Use identical weather, seed, duration and initial state when creating a comparison. Stored totals from different durations are not directly comparable; the report includes the number of days and flags differences. Historical scripts also calculate crop-yield proxies and reward-weight trade-offs; see [experiments/comparisons](../experiments/comparisons). No controller is declared universally superior by the README.
